# 测试质量宪法 v1.0

> TDD 就绪 + TDD 质量 + 测试可维护性 + 数据管理 + 回归测试
> 覆盖阶段：tickets → /tdd → /implement → /code-review → PR

## 一、TDD 就绪门禁

> 触发：/to-tickets 完成后，/tdd 启动前
> 详细清单：`~/.claude/gate-checklists/tdd-readiness-checklist.md`

/tdd 启动前必须逐条确认 6 项：

| # | 规则 | 不通过的处理 |
|:-:|------|------|
| R1 | 错误码已定义 — 每个 API 端点的错误响应含 status 码 + body 格式 | 回 spec 补充 §Implementation Decisions |
| R2 | 测试数据已指定 — 前置准备中为具体值（ID/名称/参数），非占位符 | 回 ticket 补充 §前置准备 |
| R3 | API 入口已明确 — 探针目标为完整 HTTP URL，非文件路径 | 回 ticket 补充 §代码目录 |
| R4 | 权限机制已说明 — 后端如何读取/校验权限已写清 | 回 spec 补充 |
| R5 | 测试场景全部可执行 — 无"当前环境不可实现"的项 | 降级方案或标 `[human-verify]` |
| R6 | 测试环境已就绪 — Docker/DB/用户/Token 已验证可用 | 修复环境后重试 |

**不通过 → 立即停止，补齐再继续。** 不等、不猜、不假设"后面会补"。

## 二、TDD 执行规则

> 触发：/tdd 执行中
> 原理：AI agent 可以声称"完成"但没写好——测试是唯一不可伪造的证据。

| # | 规则 | 反例 |
|:-:|------|------|
| T1 | **测试先于实现** — 测试 commit 必须在实现 commit 之前 | "我先写完代码再补测试" |
| T2 | **逐点提交** — 每个 `[auto]` AC 完成 RED→GREEN 后立即 commit | 攒 5 个 AC 一次提交 |
| T3 | **不跳过** — 简单改动可跳过 spec 评审，但不可跳过 TDD RED 阶段 | "这个太简单了不用测试" |
| T4 | **Stub 必须明确** — 未实现的接口返回 NotImplementedError / 501 / `throw new Error('Not implemented')` | 返回 `null` / `[]` / 404 冒充 🔴 |
| T5 | **一个 ticket 一个 RED commit** — 全部 AC 的失败测试写完后统一提交，标记 `TDD: RED — ticket NNN` | 部分测试仍在暂存区就开始实现 |
| T6 | **测试按接缝分层** — 优先最高可用接缝（API > 模块接口 > 单元），不穿透实现细节 | E2E 测试测了内部函数实现细节 |
| T7 | **禁止静默跳过** — 断言/交互不在条件分支内：`expect`/`click`/`check` 不包裹在 `if (count() > 0)` 中 | "元素不存在就跳过，就当测过了" |

> 详细门禁：`~/.claude/gate-checklists/test-checklist.md`（T1-T7，含签出清单 + 转换检查）

## 二点五、/tdd → /implement 转换检查

> 触发：/tdd 完成，提交前
> 目的：确认 RED 真实可信——失败原因是缺实现而非代码错误

| # | 检查项 | 反例 |
|:-:|--------|------|
| C1 | **全部失败** — 所有测试已执行，无一跳过，全部 🔴 | "大部分失败了，那两个应该也对了" |
| C2 | **失败原因正确** — 错误为 NotImplementedError / 501 / `Not implemented`，非语法错误/import 失败/配置错误 | ImportError 当 RED（实际是测试写错了） |
| C3 | **RED commit 已提交** — message 含 `TDD: RED`，可追溯 | 测试留在暂存区就开写实现 |
| C4 | **无实现混入** — RED commit 仅含测试文件 + stub，无业务逻辑 | "顺手写了个 helper"混在 RED commit |
| C5 | **AC 全覆盖** — 每条 `[auto]` AC 至少对应一个测试，输出映射表 | 写了 5 个测试但 ticket 有 6 条 AC |

> AI 自动预检命令 + 人工签出清单：`~/.claude/gate-checklists/test-checklist.md` §C1-C5 自动预检

## 二点六、RED → GREEN 测试断言切换

> 触发：C1-C5 人工确认放行后，/implement 启动前
> 目的：GREEN 测试断言真实业务行为，而非 stub 的"预期失败"

RED 阶段断言 stub 行为（`code=1`、`NotImplementedError`、空响应），
GREEN 阶段必须重写断言为真实业务行为（`code=0`、`data.list` 非空、字段值校验）。

| 阶段 | 断言目标 | 示例 |
|------|------|------|
| RED | Stub 返回"未实现" | `expect(response.code).toBe(1)` |
| GREEN | 真实业务结果 | `expect(response.code).toBe(0); expect(response.data.list.length).toBeGreaterThan(0)` |

**规则：GREEN 测试断言不可复用 RED 断言。** `/implement` 启动前必须确认断言已切换。

## 三、测试接缝

> 触发：/to-spec 撰写 Testing Decisions 时
> 模板：`~/.devflow/templates/test-plan-template.md`

| 层级 | 定义 | 适用 |
|------|------|------|
| E2E / API 探针 | 从外网/curl/Playwright 打真实 API | 用户可见行为、跨模块集成、回归 |
| 模块接口 | 调 public API/函数，不穿透实现 | 逻辑正确性、接口契约 |
| 单元 | 纯函数/算法/状态机 | 复杂计算、parser、状态迁移 |

**优先最高可用接缝**：能从 API 层测就不调内部函数；能从 public 方法测就不测 private。

## 三点五、测试数据管理

| # | 规则 |
|:-:|------|
| D1 | 测试数据与生产数据隔离 — 使用 fixture/factory/seeder，不依赖生产数据库 |
| D2 | 测试间数据独立 — 每个测试文件 setup 创建数据，teardown 清理，不共享可变状态 |
| D3 | 固定测试数据需附完整性说明 — 如使用固定 ID（sale_id=xxx），注释标注数据来源 + 有效期 |
| D4 | 共享测试数据放 `tests/fixtures/`，不嵌入测试代码 |

## 四、测试可维护性

| # | 规则 |
|:-:|------|
| M1 | 测试测试行为，不测实现 — 重构内部逻辑不应破坏测试 |
| M2 | 一个测试文件对应一个 ticket，文件名含 ticket ID（`test_ticket_001.py`） |
| M3 | 测试数据独立（fixture/factory），不依赖生产数据 |
| M4 | `[human-verify]` AC 在测试文件中用 TODO 标注，不遗漏 |

## 五、回归测试

| # | 规则 |
|:-:|------|
| RG1 | 修改共享模块/类型/工具函数 → 跑全量测试确认 0 回归 |
| RG2 | 现有测试失败 → 先判断是 bug 还是预期行为变更 → bug 则修实现，预期变更则更新测试 |
| RG3 | 删除功能 → 同步删除对应测试，不留孤儿测试 |
