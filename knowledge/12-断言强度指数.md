# 断言强度指数（ASI — Assertion Strength Index）

> 来源：STARWEST 2026 测试自动化大会，断言分级最佳实践
> 应用：C0.8 断言强度门禁 / G0 故障注入验证 / 测试质量审查
> 关联文档：[09-测试质量宪法](09-测试质量宪法.md) · [test-checklist §C0.8](../gate-checklists/test-checklist.md)

## 概述

ASI 将测试断言按**对业务正确性的保护力**分为五级。级别越高，断言越强——能检测到的回归缺陷越多，假 GREEN 风险越低。

G0 故障注入的核心原理：低级断言在注入故障后仍可能 PASS（测试"绿"但功能坏），高级断言必须 FAIL（测试真正在保护业务逻辑）。

## 五级量表

### ASI-5：精确值断言（最强）

断言输出为**具体的、可预期的值**。任何偏离都意味着回归。

| 断言 | 示例 | 能检测什么 |
|------|------|------|
| `toBe(value)` | `expect(result.count).toBe(5)` | 任何值变化 |
| `toEqual(value)` | `expect(response).toEqual({code:0, data:[...]})` | 任何字段差异 |

**G0 表现**：故障注入 → 值变化 → 测试 FAIL ✅
**假 GREEN 风险**：极低。精确值断言几乎不可能被故障绕过。

### ASI-4：结构/包含断言

断言输出**包含特定元素或匹配特定结构**。不验证完整值，但验证关键特征。

| 断言 | 示例 | 能检测什么 |
|------|------|------|
| `toContain(item)` | `expect(list).toContain('PT-001')` | 目标元素缺失 |
| `toStrictEqual(obj)` | `expect(result).toStrictEqual({id:1, name:'A'})` | 结构/类型不匹配 |
| `toMatch(pattern)` | `expect(text).toMatch(/订单号/)` | 关键文本缺失 |
| `toHaveText(text)` | `expect(el).toHaveText('保存成功')` | 文案变化 |
| `toContainText(text)` | `expect(el).toContainText('PT-')` | 订单号格式丢失 |
| `toHaveClass(cls)` | `expect(el).toHaveClass('active')` | 状态样式丢失 |
| `toHaveAttribute(name,val)` | `expect(el).toHaveAttribute('disabled')` | 交互状态错 |
| `toHaveValue(val)` | `expect(input).toHaveValue('100')` | 输入值丢失 |
| `toHaveCount(n)` | `expect(items).toHaveCount(3)` | 渲染项数变化 |
| `toBeChecked()` | `expect(checkbox).toBeChecked()` | 勾选状态错 |
| `toBeCloseTo(n)` | `expect(pi).toBeCloseTo(3.14, 2)` | 浮点精度漂移 |

**G0 表现**：故障注入 → 特征消失/结构错 → 测试 FAIL ✅
**假 GREEN 风险**：低。旁路修改可能不命中检查的特征。

### ASI-3：计数/范围断言

断言输出**满足数值范围**。不验证具体值，只验证"够不够/多不多"。

| 断言 | 示例 | 能检测什么 |
|------|------|------|
| `toBeGreaterThan(n)` | `expect(count).toBeGreaterThan(0)` | 返回完全为空 |
| `toBeGreaterThanOrEqual(n)` | `expect(count).toBeGreaterThanOrEqual(1)` | 同上 |
| `toBeLessThan(n)` | `expect(time).toBeLessThan(1000)` | 性能严重退化 |
| `toBeLessThanOrEqual(n)` | `expect(errors).toBeLessThanOrEqual(0)` | 出现错误 |
| `toHaveLength(n)` | `expect(list).toHaveLength(5)` | 列表项数变化 |

**G0 表现**：故障注入 → 可能 PASS 也可能 FAIL，取决于故障类型
- `expect(count).toBeGreaterThan(0)` + 搜索过滤失效 → 返 19 条 > 0 → PASS（假 GREEN）❌
- `expect(count).toBe(1)` + 搜索过滤失效 → 返 19 ≠ 1 → FAIL ✅

**假 GREEN 风险**：**中高**。这是最常见的盲区——"有结果"不等于"结果正确"。搜索/过滤类测试的 ASI-3 `> 0` 断言无法区分"过滤了"和"全返了"。

> ⚠️ ASI-3 是本级别最大的陷阱：计数 > 0 的测试在功能完全失效时仍然可能 PASS。G0 故障注入是唯一可靠的区分手段。

### ASI-2：存在性断言

断言元素/属性**存在**。验证不到任何业务值。

| 断言 | 示例 | 能检测什么 |
|------|------|------|
| `toBeVisible()` | `expect(table).toBeVisible()` | 元素完全不渲染 |
| `toBeDefined()` | `expect(result).toBeDefined()` | 返回 undefined |
| `toBeTruthy()` | `expect(data).toBeTruthy()` | 返回 falsy 值 |
| `toBeNull()` | `expect(error).toBeNull()` | 出现非 null 错误 |
| `toBeFalsy()` | `expect(error).toBeFalsy()` | 出现 truthy 错误 |

**G0 表现**：故障注入 → 元素仍在 DOM 中 → PASS（假 GREEN）❌
**假 GREEN 风险**：**高**。元素可见 ≠ 功能正确。42 处假通过案例中，ASI-2 断言占了绝大多数。

### ASI-1：恒真断言（最弱）

断言**在任何情况下都成立**——要么数学恒真，要么测试了无关属性。

| 断言 | 示例 | 为什么是恒真 |
|------|------|------|
| `toBeGreaterThanOrEqual(0)` | `expect(count).toBeGreaterThanOrEqual(0)` | 计数永远不会 < 0 |
| `expect(true).toBe(true)` | 硬编码 | 永远通过 |
| `toBeDefined()` on 常量 | `expect(API_URL).toBeDefined()` | 编译期常量 |

**G0 表现**：任何故障 → 断言仍 PASS → 永远不 FAIL ❌
**假 GREEN 风险**：**确定假**。恒真断言是测试装饰，不提供任何保护。

## C0.8 与 ASI 的映射

C0.8 的"弱断言"定义 = ASI-1 + ASI-2。C0.8 的"强断言"定义 = ASI-3 + ASI-4 + ASI-5。

```
弱断言（C0.8 拦截目标）：
  ASI-1 恒真 → toBeGreaterThanOrEqual(0) / 硬编码 true
  ASI-2 存在 → toBeVisible / toBeDefined / toBeTruthy / toBeNull / toBeFalsy

强断言（C0.8 放行）：
  ASI-3 计数/范围 → toBeGreaterThan / toHaveLength / toBeLessThan
  ASI-4 结构/包含 → toContain / toStrictEqual / toMatch / web-first matchers
  ASI-5 精确值   → toBe / toEqual
```

**注意**：ASI-3 被归类为"强"，但它是强断言中最弱的——在搜索/过滤场景下仍可能假 GREEN。C0.8 是 grep 级扫描，无法区分使用场景。ASI-3 的语义强度需要 G0 故障注入或人工审查来验证。

## 场景决策矩阵

| 测试场景 | 最低要求 | 推荐 |
|------|:--:|:--:|
| CRUD 创建 → 验证创建成功 | ASI-4（toContain/toBeChecked） | ASI-5（toEqual 完整对象） |
| 搜索/过滤 → 验证过滤生效 | **ASI-5**（toBe/exact count） | ASI-5 + G0 注入 |
| 删除 → 验证已删除 | ASI-4（toHaveCount 减 1） | ASI-5 + toContain 确认不存在 |
| 列表展示 → 验证有数据 | ASI-3（toHaveLength > 0） | ASI-4（toContain 具体项） |
| 表单提交 → 验证成功提示 | ASI-4（toHaveText '成功'） | ASI-5（验证后续状态变化） |
| 权限控制 → 验证不可见 | ASI-2（toBeNull/toBeFalsy） | ASI-5（精确验证 403 响应） |

---

## 提升断言强度的步骤

1. **识别**：跑 C0.8 看弱断言占比
2. **分类**：每个弱断言按 ASI 分级归类
3. **升级**：每次升级一级（ASI-2 → ASI-3 → ASI-4 → ASI-5），不追求一步到 ASI-5
4. **验证**：升级后用 G0 故障注入确认——注入故障后测试必须 FAIL
5. **标注**：遗留的 ASI-2 断言标注理由（如权限测试只能验证 null）
