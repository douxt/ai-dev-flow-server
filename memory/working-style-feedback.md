用户在一次长调试会话中反复纠正我的四个工作习惯：

1. **说完再做，等用户认可再执行**。不要"说完就闷头做"。流程应是：讲清要做什么+为什么 → 用户点头 → 再动手。
2. **动手前先给前情提要**。讲清"现在在哪、要去哪、目的是什么"，否则用户无从判断我做得对不对。
3. **不要猜，做小实验验证**。反复"我觉得可能是……"是坏味道。能读的文件就读、能下载的图就下载看、能 dump 的结构就 dump、能 curl 的链接就 curl。自己确认，别让用户替我验证。
4. **先看清数据结构再改**。这次 quote 提取错了三轮，根因就是没先 dump 看清 prompt 真实结构就动手。
5. **决策讨论用对话，不用 AskUserQuestion 弹窗**（2026-07-15 补）。多轮拷问/探讨式决策时用户明确要求："拷问能否不用弹窗？很多时候都是探讨式的，大部分都走 Other，不如直接对话表达想法"。弹窗适合封闭单选；开放式权衡一律对话式，一次一个问题并附推荐。另：用户显式指令沉淀记忆最常用"记住"，谴责式措辞反而少用。

**Why:** 用户明确表达对"闷头猜、反复试错、慢"的强烈不满（"你反应很慢"、"不要总是猜想"、"你要自己确认，做小实验"）。跳过对齐直接执行会做错方向、浪费大量往返；靠猜代替验证会得出错误结论（如一度把 `combine-forward-message` 读成 false）。

**How to apply:** 每个非平凡动作前，用一两句说清目的和做法，等用户认可；遇到未知先设计最小实验去证实（读源码/下载/dump/实测），而不是推测；改代码前先确认真实数据形态。相关技术踩坑见 [[silent-observer-langbot-context]]。
